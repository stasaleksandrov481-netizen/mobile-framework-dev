# CORTEX: аудит готовности к тестированию

Актуально на 16.11.2026. Проанализирован выпущенный Android 1.0.11, подготовлены исходники **кандидата 1.0.12 (versionCode 112)**, проверены веб, Edge Function, реальные метаданные Supabase/Vercel и GitHub Actions. Новый APK не собран, реального тестирования на Android-устройствах **не было**.

## P0/P1, исправлено в этой ветке

1. Синхронизированы миграции GitHub с применённой схемой Supabase. Четыре версии имен файлов исправлены, две отсутствовавшие миграции извлечены из `supabase_migrations` с проверкой MD5. Неприменённая конфликтующая миграция архивирована.
2. Совмещены работающее Redis-кэширование и начисление 5 000 бонусных токенов из Edge Function v30 с более новыми подписками и идентификаторами устройств из репозитория. Прямой деплой прежнего GitHub-кода мог откатить бонусы и Redis.
3. Убрана автоматическая публичная публикация APK при push в `main`. Публичная бета теперь требует ручного запуска GitHub Actions, релиз маркируется prerelease.
4. Отсутствие строки конфигурации больше не открывает доступ к закрытой бете (fail-closed).
5. Оборванный поток ответа ИИ больше не принимается за успешный; неоконченный план инструментов не исполняется.
6. Android сохраняет возврат из Яндекс ID даже при холодном запуске WebView, слишком большой запрос получает немедленную ошибку.
7. Улучшен ввод шестизначного кода: шесть полей, вставка кода целиком, клавиатурная навигация, таймер повторной отправки, обновление исходной вкладки после подтверждения ссылки. Требование пароля согласовано с Android (минимум 10 символов для регистрации).
8. CI проверяет не только Android и сервер, но также сборку сайта и админки.

## Проверки

- Сервер/платежи: **34 из 34 тестов пройдены**, включая сценарии ЗБТ, проверку долгого нажатия и изолированную имитацию параллельных запросов.
- Веб: Next build и TypeScript проверены.
- Runtime-зависимости двух веб-пакетов: `npm audit --omit=dev` не выявил известных уязвимостей на момент проверки.
- Android JVM-тесты и APK должны быть отдельно собраны GitHub Actions; в локальном окружении Android SDK отсутствует.

### Имитационное тестирование, 16.11.2026

В `supabase/functions/cortex/handler.test.ts` добавлены пять сценариев с подставными
Supabase, OpenRouter и устройствами. Они не отправляют сообщения реальным пользователям,
не вызывают платёжный провайдер и не расходуют токены API:

1. Путь пользователя: стартовый статус, регистрация, неверный и верный код,
   авторизованный чат, заявка в поддержку, чтение ответа, выход.
2. Одиннадцать повреждённых или некорректных запросов к ИИ отклоняются до вызова модели.
3. Неисправный JSON и слишком большой запрос отклоняются ответами 400 и 413.
4. Потеря соединения после получения команды Android, но до `[DONE]`, не передаёт
   незавершённую команду на выполнение.
5. Десять параллельных установок получают разные идентификаторы и независимую квоту;
   резервная модель активируется при отказе первой.
6. Дополнительная имитация 50, 200 и 500 одновременных запросов `status` использует только
   локальные моки. Все запросы вернули 200, идентификаторы установок не смешались, ИИ не вызывался.
   В одном запуске p95 составил **13,1 / 65,6 / 76,7 мс**, p99 **13,5 / 66,4 / 77,8 мс**.
   Это измерение **скорости тестового обработчика**, не пропускная способность продакшена.

Локальный запуск: `node --experimental-transform-types --test supabase/functions/cortex/handler.test.ts supabase/functions/cortex/redis.test.ts cortex-control/tests/billing.test.js`.

**Не охвачено:** выполнение команд на реальном устройстве, настоящие OAuth/почтовые
провайдеры, проверка платежей и конкурентных транзакций PostgreSQL, отображение
экранов в Android WebView. Попытка запустить Chromium для имитации WebView была
остановлена ограничением окружения (`socket() failed: Operation not permitted`).

### Длинные задачи и универсальное управление экраном, 16.11.2026

- Расширен цикл визуального агента: до 12 раундов планирования, 80 попыток экранных действий
  и 12 минут работы на один запуск. Окончание лимита оставляет возможность ручного продолжения.
- `done: true` вместе с выполненными шагами больше не означает автоматического успеха:
  CORTEX запрашивает финальную проверку по текущему доступному экрану.
- Повтор одного и того же плана без подтверждённого прогресса останавливается после
  нескольких итераций, даже если Android принял касание, но экран не изменился.
  Это предотвращает повторные нажатия без наблюдаемого результата.
- Добавлено `long_press` для обычных и распознанных экранных элементов. Подозрительные
  команды требуют подтверждения; закрытые/приватные экраны остаются недоступными.
- Новые локальные команды без затрат ИИ: таймер, будильник, поиск в интернете и картах,
  копирование текста, режим звука/вибрации, открытие видеокамеры, набор номера и черновик SMS. Действия, требующие
  подтверждения в системном приложении, считаются передачей управления, а не завершением.
- После передачи управления будильнику, таймеру, набору номера или черновику SMS
  локальная цепочка ставится на паузу до ручного продолжения, чтобы не выполнялись
  дальнейшие команды до проверки пользователем.

### Обновления WebView без замены APK

Добавлен отключённый по умолчанию механизм подписанных обновлений HTML/CSS/JS через
HTTPS и приватное хранилище. Подпись `SHA256withRSA` и SHA-256 архива проверяются до
активации, предыдущая версия сохраняется для отката. Три теста проверяют подпись,
комплектность, воспроизводимость архива и отказ после подмены манифеста.

Для включения до первого выпуска APK требуются repository variables
`CORTEX_WEB_UPDATE_ROOT` и `CORTEX_WEB_UPDATE_PUBLIC_KEY`, отдельный защищённый RSA-ключ
и HTTPS-хостинг подписанных трёх файлов. См. `docs/WEBVIEW_OTA.md`.
Нативный Kotlin/Android-код таким способом обновлять нельзя.

**Проверка Android-кода пока не завершена:** новые Kotlin-тесты добавлены, но локально
нет Android SDK/Gradle. Перед раздачей APK обязательно запустить GitHub Actions и
проверить длительную задачу в фоне на физических устройствах. Android может завершить
процесс, а живой экран и подтверждения нельзя безопасно автоматизировать без участия пользователя.

## Оставшиеся блокеры ЗБТ

1. Проверить GitHub Actions Android build; провести испытания APK на физических Android 8–15+, включая Samsung, Xiaomi и Pixel, без разрешений, при падении WebView, после перезапуска, на фоне и при нестабильном интернете.
2. Проверить вход и выход, неверные коды, OAuth callback из холодного процесса, отзыв приглашения, запрет незарегистрированных устройств, работу одного приглашения на нескольких устройствах.
3. Проверить микрофон и Foreground Services, островок, Accessibility, горячее слово, уведомления и фоновые сценарии после перезагрузки Android.
4. Отдельно испытать все действия с повышенным риском: оплата, удаление, отправка сообщения, публикация, доступ к экрану; каждое должно требовать подтверждения.
5. Разворачивать Edge Function после сверки конфигурации с текущей v30 и тестов `/v1/status`, `/v1/chat`, `/v1/subscription`, бонусов и Redis. Не менять production без полного smoke-теста.

## Оставшиеся блокеры ОБТ

- Не подключён проверенный crash/ANR reporting с явным согласием на необязательную аналитику
  и удалением/маскированием личных данных. Встроенный канал поддержки и скриншоты существуют,
  но не заменяют автоматическую диагностику вылетов.
- Отсутствует реальный staging-нагрузочный прогон 50/200/500 клиентов с PostgreSQL,
  Redis, SSE и платным/бесплатным ИИ. Локальная имитация выше не определяет ёмкость сервера.
- Пять `SECURITY DEFINER` админ-функций доступны `authenticated`. По метаданным БД все проверяют MFA AAL2, но не проверяют актуальность `session_id` в `auth.sessions`. Нужны исправление и тест отзыва админской сессии. [Supabase advisor](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).
- В Supabase Auth выключена проверка скомпрометированных паролей. [Инструкция](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- База сообщает о шести неиндексированных внешних ключах и неоптимальных RLS-политиках. Нужен план оптимизации под массовую нагрузку. [Advisor](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys).
- Не закрыты юридические вопросы из `cortex-web/legal/LAUNCH-CHECKLIST.md`: оператор данных, первичная локализация, удаление аккаунта, подтверждённые согласия и реальная поддержка.
- Нужны нагрузочные испытания и наблюдение за ошибками API и Android после ограниченного ЗБТ.

**Решение:** ЗБТ — условный допуск только после CI и физических испытаний. ОБТ — пока no-go; дата 20 ноября не является автоматическим сигналом запуска.
