# CORTEX для Android

CORTEX 1.0.10 использует общую очередь визуальных задач для чата, островка, сценариев и расписания. Для локальных шагов приложение читает дерево Android и проверяет результат. Если дерево не содержит нужного текста, на Android 11 и новее CORTEX может распознать русский или английский текст на снимке экрана. Модель, версия Android, частота экрана и основные параметры считываются с устройства. Для сложных целей серверный шлюз запрашивает структурированный план, проверяет его и передаёт шаги движку Android.

## Возможности беты

- В разделе «Вызов → Расписание» создаются, редактируются и отменяются напоминания и действия. Там же видны повторения, ожидающие поручения и история.
- Скажите «через десять минут напомни достать курицу» или «завтра в восемь утра напомни». Напоминание появляется в островке либо в системном уведомлении. С ним можно отметить дело, отложить на пять минут или открыть расписание.
- Для команды «через полчаса напиши папе, что я буду дома» CORTEX уточнит приложение и название переписки. При выполнении CORTEX сверяет получателя, показывает текст и ждёт подтверждения отправки. При выключенном экране отложенное действие ждёт запуска из расписания.
- В разделе «Вызов → Сценарии» можно собрать шаги, назначить голосовые фразы и записать точку касанием экрана. Кнопка «Запустить» выполняет шаги на устройстве. В меню сценария можно сохранить его копию в JSON. ИИ может предложить черновик для редактирования перед сохранением.
- Редактор островка доступен во вкладке «Вызов». Энергорежимы и обращение к пользователю находятся в настройках. Голосовой режим зависит от разрешений и поддержки офлайн-распознавания Android.
- Центральная кнопка CORTEX открывает временный чат. Чтобы сохранить диалог, создайте его кнопкой «Новый чат» во вкладке «Чаты».

## Установка и сборка

- Android 8.0 или новее с актуальным Android System WebView. Голосовой вызов требует поддержки офлайн-распознавания речи на устройстве.
- Для сборки нужны JDK 17 или совместимая версия, Gradle 8.13 и Android SDK Platform / Build Tools 36.
- Команда `./gradlew :app:assembleDebug` создаёт APK в `app/build/outputs/apk/debug/`.
- Для уже установленной Preview 1.0.5 используйте `-PcortexPreview=true`. Он сохраняет её идентификатор `app.cortex.assistant.preview.v105`. Версия 1.0.10 имеет код 110 в обеих сборках.
- Основная версия сохраняет имя **CORTEX** и идентификатор `app.cortex.assistant`. Для установки поверх старой версии Android сверяет сертификат APK.

### Обновление исходников на GitHub

Синхронизируйте папку проекта вместе со скрытой папкой `.github` и удалениями файлов. Копирование поверх старой папки может оставить исходники озвучки из 1.0.5. При обновлении с 1.0.5 в репозитории нужно удалить `app/src/main/assets/voice/`, `voices/catalog.json`, `app/voice-runtimes.gradle`, `app/src/test/java/app/cortex/assistant/RuVoicePresetTest.kt` и семь классов из `app/src/main/java/app/cortex/assistant/`: `CortexVoiceOutput.kt`, `LocalVoice.kt`, `RuVoicePreset.kt`, `SileroVoice.kt`, `VoiceDownload.kt`, `VoicePack.kt` и `VoiceStore.kt`. Проверьте, что в ветке `main` обновился файл `.github/workflows/android-apk.yml`.

### Подпись обновления

Начиная с будущего выпуска 1.0.12 используется новый постоянный сертификат CORTEX от 16.11.2026. Его SHA-256 — `6a7967ebe2d0a5de51c02140ceade238bf1769b47bb2dcffc80bc955d650cf6b`. GitHub проверяет отпечаток до публикации APK. Выпуски до 1.0.11 включительно подписаны другим сертификатом. Для перехода на 1.0.12 требуется удалить старое приложение с сохранением важных данных; последующие версии с новым сертификатом обновляются поверх 1.0.12.

В **Settings → Secrets and variables → Actions** один раз добавьте четыре секрета из комплекта подписи для GitHub. Ключ и пароли храните отдельно от репозитория.

| Секрет | Значение |
| --- | --- |
| `CORTEX_KEYSTORE_B64` | Содержимое хранилища ключей в Base64 |
| `CORTEX_STORE_PASSWORD` | Пароль хранилища |
| `CORTEX_KEY_ALIAS` | Имя ключа `cortex` |
| `CORTEX_KEY_PASSWORD` | Пароль ключа |

Подписанные WebView-обновления необязательны. Если обе переменные CORTEX_WEB_UPDATE_ROOT и CORTEX_WEB_UPDATE_PUBLIC_KEY не настроены, APK использует встроенный интерфейс, а неподписанные веб-обновления остаются запрещены.

Для выпуска выберите **Actions → CORTEX Android APK and Release → Run workflow**, ветку `main` и включённый `publish`. Push в `main` с настроенными секретами тоже публикует выпуск. Чтобы только проверить сборку и тесты, отключите `publish` при ручном запуске.

Для локальной сборки задайте `CORTEX_KEYSTORE_FILE` с абсолютным путём к хранилищу, `CORTEX_STORE_PASSWORD`, `CORTEX_KEY_ALIAS` и `CORTEX_KEY_PASSWORD`, затем выполните `./gradlew :app:assembleRelease`. Для уже установленной Preview используйте `-PcortexPreview=true` и ключ её предыдущей сборки.

## Управление экраном

Включите «CORTEX — управление экраном» в специальных возможностях Android через «Профиль → Разрешения Android». Откройте чат или островок и скажите, что нужно сделать. Пример локальной цепочки — «Открой Настройки → Дисплей, прокрути вниз». CORTEX открывает приложение напрямую и проверяет появление окна. Режим «Показывать запуск на экране» в разделе «Вызов» оставляет видимый поиск ярлыка через рабочий стол. Внутри приложений CORTEX использует доступные элементы Android. Сложный запрос можно начать со слова «Действие:», чтобы явно выбрать управление телефоном.

Примеры локальных запросов:

- «Бро, помоги, у меня вайфай выключается и включается модем». CORTEX проверяет Wi-Fi и активный транспорт, ищет переключатель точки доступа и восстанавливает Wi-Fi, если это допускают настройки Android. «Почему выключается Wi-Fi?» запускает диагностику. CORTEX указывает, что подтвердил Android и какие изменения действительно произошли.
- «Открой Telegram, зайди в переписку «Анна» и напиши сообщение: „Привет!“». CORTEX ищет точное название чата, сверяет заголовок переписки и текст в поле, затем запрашивает подтверждение отправки. При неизвестном получателе или тексте CORTEX сначала уточняет. Команда с «без отправки» оставляет текст в поле ввода. Поиск работает с приложениями, которые предоставляют доступные элементы поиска, результатов и переписки.
- «Сколько заряда?», «Включи фонарик», «Домой», «Свайпни вниз» и «Нажми Настройки» выполняются локально при доступности соответствующего действия.

Во время визуальной задачи текущий шаг и кнопка остановки видны в островке у камеры, если островок включён. Команда «Кортекс, убери островок» скрывает его до следующего голосового вызова. «Кортекс, выключись» останавливает задачу, островок, фоновое прослушивание и проверку ответов поддержки. Включить фоновую работу снова можно на вкладке «Вызов».

При сбое можно продолжить с текущего экрана командой «Продолжи». План на паузе хранится до завершения процесса CORTEX. В «Разрешениях Android» можно открыть журнал задач.

Снимки для распознавания обрабатываются на устройстве. Локальные команды и их ответы исключаются из контекста разговорной модели. Для сложной визуальной задачи за один запуск допускается до двух запросов модели. Передача текста открытого экрана серверу и OpenRouter требует согласия, которое можно отозвать в «Профиль → О приложении → Конфиденциальность». Для отправки, удаления и других необратимых действий CORTEX запрашивает подтверждение. Пароли, системные запросы доступа и защищённые окна требуют действий пользователя. Для оцениваемой работы на Учи.ру пользователь сам сдаёт результат. Возможность выполнить шаг зависит от интерфейса конкретного приложения.

Модели распознавания русского и английского взяты из [tessdata_fast 4.1.0](https://github.com/tesseract-ocr/tessdata_fast/tree/65727574dfcd264acbb0c3e07860e4e9e9b22185) под Apache-2.0. Лицензия включена в `app/src/main/assets/ocr/`.

## Голосовое управление

Разрешите микрофон и включите «Кортекс» в настройках управления телефоном для активации в фоне. Микрофон в чате поддерживает диктовку, а кнопка с волной отправляет распознанную команду. Ответы и статусы отображаются текстом.

## Вход и развёртывание

1. Примените миграцию `supabase/migrations/20261115122057_cortex_token_budget.sql` в существующем проекте CORTEX. Затем примените миграцию cortex_guest_and_account_quota для раздельных лимитов гостя и аккаунта.
2. Для Яндекс ID зарегистрируйте приложение для авторизации и выберите платформу «Веб-сервисы». Дайте доступ `login:email` и `login:info`, затем сохраните точный Redirect URI `https://jjcqrjztxohnifmziksy.supabase.co/functions/v1/cortex/v1/auth/callback/yandex`. Добавьте Client ID и Client secret в Edge Function Secrets под именами `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`.
3. В Supabase Auth разрешите вход по почте и регистрацию новых пользователей, затем включите подтверждение адреса. В Custom SMTP укажите сервер, порт, отправителя и учётные данные почтового провайдера. Добавьте `{{ .Token }}` в письма Confirm signup и Reset password. В обоих шаблонах нужен видимый код. Ссылку подтверждения можно сохранить для панели управления. У существующих пользователей с подтверждённым адресом доступен вход по паролю во время настройки SMTP. После настройки писем добавьте `CORTEX_EMAIL_AUTH=true` в Edge Function Secrets.
4. Разверните Edge Function `cortex` со шлюзом JWT в режиме `--no-verify-jwt`. Маршруты проверяют собственную сессию CORTEX или гостевой токен установки. Соберите панель в папке `cortex-control` командой `npm ci && npm run build` и обновите её на действующем хостинге.
5. Выпустите APK с текущим постоянным сертификатом CORTEX. Настройки подписи и отпечаток описаны выше.

Код Яндекс OAuth обменивается на сервере с PKCE. Приложение открывает внешний браузер, а сессию получает отдельным HTTPS-запросом и шифрует через Android Keystore. Для старого профиля Supabase используйте восстановление пароля на прежнюю почту. Яндекс ID имеет свой идентификатор аккаунта. При первом входе локальные данные гостя привязываются к профилю на этом устройстве. Чаты, заметки и сценарии хранятся на устройстве.

## Токены и панель управления

Суточный лимит по умолчанию составляет 5 000 токенов для гостя и 20 000 токенов после входа. Локальные действия выполняются без обращения к облаку. Счётчик использует входные и выходные токены из метаданных OpenRouter. Остаток и расход за прошедшие семь дней отображаются в профиле. Сброс происходит в 03:00 по Москве.

Шлюз учитывает каждый запуск облачной модели, включая резервные попытки. Общий предел по умолчанию — 50 запусков в сутки и 20 за скользящую минуту. Укажите подтверждённый предел аккаунта через `CORTEX_DAILY_REQUEST_LIMIT` и при необходимости `CORTEX_MINUTE_REQUEST_LIMIT` в Supabase Edge Function Secrets. При наличии права на 1 000 бесплатных запросов в сутки серверный предел можно поднять до 1 000. Модель и пределы в рамках этих значений меняются из панели. Ключ OpenRouter хранится в `OPENROUTER_API_KEY` или существующем Vault.

Изменять лимиты и видеть записи по ID могут владелец и администратор с подтверждённым MFA. Панель использует адрес `https://cortex-control-phi.vercel.app/` и настройки redirect Supabase Auth для этого адреса.

Проверьте шлюз командой `node --experimental-transform-types --test supabase/functions/cortex/handler.test.ts`.
Проверьте разбор плана и обработку голосового вызова командой `./gradlew :app:testDebugUnitTest`.
Для сборки панели откройте папку cortex-control и выполните npm ci и npm run build.

Миграция Supabase после удаления озвучки переносит прежний каталог в закрытую схему и убирает его из публичного API.

## Подписки и подготовка беты 1.0.11

1. Примените обе миграции подписок и учёта аккаунтов, затем обновите Edge Function `cortex` и проект Vercel с корнем `cortex-control`. Соберите Android после обновления серверов. Сброс токенов остаётся в 03:00 МСК.
2. Во время беты оставьте оплату закрытой. Без `CORTEX_BILLING_MODE=live` Vercel не формирует запросы на оплату Robokassa. В режиме `test` серверные операции используют отдельные тестовые записи. Для имитации оплаты нужен отдельный `CORTEX_BILLING_TEST_KEY`, и тестовое подтверждение не выдаёт действующий тариф.
3. После договора настройте на Vercel `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_PUBLISHABLE_KEY`, `CORTEX_BILLING_TOKEN`, `ROBOKASSA_MERCHANT_LOGIN`, `ROBOKASSA_PASSWORD_1`, `ROBOKASSA_PASSWORD_2`, `ROBOKASSA_HASH_ALGORITHM=md5` (или значение из кабинета), `ROBOKASSA_LIVE_APPROVED=true` только после полной проверки. Для ResultURL (POST) укажите `https://<публичный-домен-cortex-control>/api/billing?webhook=1`; этот адрес должен подтверждать сумму, UUID заказа и подпись, возвращая `OK<InvId>`. Настройте SuccessURL/FailURL на реальные публичные страницы. На Edge задайте тот же серверный `CORTEX_BILLING_TOKEN` и HTTPS-адрес `CORTEX_BILLING_ORIGIN`.
4. Для платного ИИ нужен отдельный ключ `CORTEX_PAID_OPENROUTER_KEY` с лимитом расходов на стороне OpenRouter. Платные запросы CORTEX по умолчанию сначала пробуют `anthropic/claude-haiku-5.5` из расширенной квоты, затем настроенные резервные модели `CORTEX_PAID_FAST_MODEL` и `CORTEX_PAID_DEEP_MODEL`. У бесплатных аккаунтов остаются бесплатные модели; Haiku не запускается без платного ключа и действующей подписки. Для Haiku используется безопасный потолок $0.60 за миллион токенов на входе и выходе, учитываемый в резерве расширенной квоты. В БД начальный обеспеченный бюджет составляет $8 из $10. Резервы рассчитываются по худшему сценарию полного расходования квоты. Не увеличивайте обеспеченный бюджет через панель, пока средства не зачислены у провайдера. После проверки платежей и финансирования включите `CORTEX_BILLING_CHECKOUT=true` на Edge и разрешение оплаты в панели.
5. Оплата сейчас рассчитана на подтверждаемый месячный платёж. Продление выполняется новым платежом. Смена платного тарифа применяется после текущего оплаченного периода. Автоматическое продление не включено. Возвраты пока оформляются через личный кабинет Robokassa; прямой Refund API не активирован, поскольку требует Password #3 и идентификатор операции.
6. Админ-панель требует роль и второй фактор. Доступ на время техработ выдаётся отдельно на указанный срок по `@id` из профиля и не даёт административных прав. Обзор считает устройства и открытия по Москве. При обновлении сохраняется найденная дата прежней установки. Сброс телефона, другой Android-профиль или подпись приложения меняют идентификатор устройства.
