# Правила работы ИИ-агентов с CORTEX

> Этот файл обязателен к прочтению **перед любым изменением**. Действует для Android, сайта, админки, Supabase и GitHub Actions.

## Сначала сверить действующий релиз

- Репозиторий: `stasaleksandrov481-netizen/mobile-framework-dev`.
- Android: `app/`; интерфейс: `app/src/main/assets/web/`; нативные функции: `app/src/main/java/app/cortex/assistant/`.
- Сайт: `cortex-web/`; служебная панель: `cortex-control/`.
- Vercel production: проект `mobile-framework-dev` (Syndicate), домен `cortexapp.ru`. На 17.11.2026 production связан с `main`; **это не означает, что Android APK с `main` имеет одобренный пользователем интерфейс**.
- Supabase: проект `jjcqrjztxohnifmziksy`, Edge Function `cortex`. На 17.11.2026 **живая версия 44 новее серверных исходников в `main`**: в ней есть `cortex_ai_device_identity`, `settings.ts` и другие серверные изменения. **Запрещено выкатывать Edge Function из `main`/PR без сверки каждого файла с живой версией и проверки совместимости.**
- Android `main` по `app/build.gradle.kts`: `1.0.14` / `114`. Версия интерфейса, которую пользователь считает правильной, пока не подтверждена. Не выпускать и не распространять новый APK, пока не установлен её точный commit SHA.

## Обязательная последовательность

1. Проверить `git status`, текущую ветку, последний коммит, запущенные PR/CI, состояние Vercel production и Supabase Edge Function. Не работать автоматически в `main` только потому, что он default.
2. Уточнить границы задачи и найти источник правды для затрагиваемого компонента. Если ветки расходятся или runtime новее GitHub, **остановить публикацию**, зафиксировать конфликт в `docs/AGENT_HANDOFF.md` и согласовать путь с пользователем.
3. Работать в отдельной целевой ветке и маленьких проверяемых коммитах. Не перезаписывать файлы, которые параллельно меняют другие агенты. Никаких force-push, массовых удалений веток, сбросов или секретов в коммитах.
4. Проверить соответствующие тесты, линтер, сборку Android, security scan и, при UI-изменениях, фактические скриншоты экрана. Зелёный CI **не доказывает**, что пользователь одобрил новый дизайн.
5. Перед изменением production проверить **команду/проект/ветку/commit SHA/окружение**. Сверить конфигурацию и трафик, сохранить rollback-кандидат. Не деплоить Supabase DB/Edge из устаревшей копии.
6. **После каждого изменения, PR, деплоя, отката или выявленного расхождения обновить `docs/AGENT_HANDOFF.md`**: UTC-дата, агент/задача, ветка и SHA, изменённые файлы, назначение, тесты, deployment ID/состояние, дальнейшие шаги, нерешённые риски. Оставить следующий шаг другому агенту. В PR также кратко указать эти сведения.

## Критичные договорённости

- Гостевые ИИ-квоты, доступ к ИИ, платежи и подтверждение подписки всегда проверяются на сервере; не доверять локальным счётчикам, заголовкам или параметрам цены.
- `X-Cortex-Device` содержит идентификатор Android, подделывается клиентом и **не является аттестацией устройства**. Не писать raw ID в логи/базу. Не считать один Android ID полноценной защитой от злоупотреблений.
- Не обходить RLS, права `service_role`, подписи платежных webhooks, проверку токенов, ограничения API. Не включать публичную административную панель ради отладки.
- Для интерфейса: любое изменение дизайна, островка или WebView должно сохранять одобренный вариант. Если пользователь сообщил «интерфейс не тот», **заморозить релиз и сравнить APK/ветку**.
- Не публиковать ключи, токены, PII и детали внутренних сессий в сообщениях, PR, тестовых артефактах или документации.
