# CORTEX. Сайт приложения

Стек: Next.js 16 (App Router), React 19, TypeScript. Шрифт Onest Variable хранится локально. Сайт оформлен в чёрно-белом стиле Android-приложения.

## Запуск

```bash
npm ci
npm run dev
npm run build
npm start
```

Сайт открывается на http://localhost:3000. Для Vercel корневая директория проекта: `cortex-web`.

## Что готово

- На лендинге больше нет недостоверной 3D-модели телефона.
- Отдельная страница `/register` с формой слева и лёгкой сеткой на canvas справа. На экранах до 900 px декоративная панель полностью скрыта.
- Сетка работает без WebGL и не перерисовывается непрерывно в состоянии покоя; в центре вместо круга — типографика.
- Локальный Onest Variable без Google Fonts.
- Одноэкранный адаптивный лендинг без декоративных разделителей и второстепенных секций.
- Форма регистрации и подтверждения email использует тот же Supabase Auth-проект, что и Android.
- Предрегистрации сохраняются в таблицу `cortex_preregistrations` с RLS; бонус 5 000 токенов **резервируется** до беты, он не расходуется и не начисляется в AI-бюджет до подключения серверного механизма выдачи.
- Ссылка на установку скрыта до 20.11.2026 и появляется только при заданном `NEXT_PUBLIC_CORTEX_ANDROID_DOWNLOAD_URL`.
- SEO title/description/OpenGraph, favicon, базовые HTTP-заголовки безопасности.
- В `app/layout.tsx` добавлен `mailru-domain` для подтверждения VK Workspace.
- Разделы `/privacy`, `/terms` и `/permissions` описывают данные, правила раннего доступа, разрешения и ИИ. Юридические проекты с обязательными реквизитами и чек-листом лежат в `legal/`.
- Серверный модуль для отдельной Upstash Redis (`lib/redis.ts`) и `GET /api/status`, который проверяет доступность Redis без раскрытия ключей.
- Честное позиционирование: публичная бета запланирована на **20.11.2026**, скачивание APK пока не включено.

## Upstash Redis

Создайте **отдельную** Redis-базу для CORTEX. Не используйте `smetraProduction`.

1. Добавьте в окружение Vercel значения `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` из Upstash. Эти переменные серверные, префикс `NEXT_PUBLIC_` запрещён.
2. Локально используйте `.env.local` по образцу `.env.example` (файл исключён из Git).
3. Проверьте `/api/status`: ответ `{"status":"ok"}` означает, что сервер соединился с Redis. Ответ 503 означает, что конфигурация недоступна или соединение не удалось.

Сайт может открываться без Redis. Эта интеграция готовит серверное соединение, но пока не хранит пользовательские данные.

## Предрегистрация

1. SQL-миграция `supabase/migrations/20261115171814_cortex_preregistration.sql` **применена к проекту CORTEX** (`jjcqrjztxohnifmziksy`). Миграция создаёт таблицу, ограничивает доступ с помощью RLS и запрещает клиенту менять бонусные начисления.
2. В Supabase Auth разрешить email/password signup, включить подтверждение почты и добавить `https://cortexapp.ru/auth/callback` в список разрешённых Redirect URLs. Email-шаблон должен содержать ссылку подтверждения либо код OTP.
3. При необходимости переопределить публичные значения `NEXT_PUBLIC_CORTEX_SUPABASE_URL` и `NEXT_PUBLIC_CORTEX_SUPABASE_PUBLISHABLE_KEY` (в коде уже заданы те же публичные значения, что используются в `cortex-control`).
4. Перед стартом беты настроить почтового провайдера и **серверную** отправку уведомлений по `notify_opt_in`, не передавая email-список браузеру. Само наличие флага согласия ещё не отправляет письмо.
5. Перед начислением бонуса реализовать в серверном `cortex_ai_reserve` однократное списание бонусных кредитов по подтверждённым аккаунтам. Колонка `bonus_tokens` — резерв, изменять её из браузера нельзя.
6. Для автоматического входа после установки Android-разработчику нужна обработка App Link с **одноразовым серверным кодом**, привязанным к Supabase Auth ID. Постоянный bearer-токен нельзя помещать в URL. Пока Android не поддерживает обмен кодом, пользователь сможет войти с той же почтой и паролем.

В Vercel задать `NEXT_PUBLIC_CORTEX_ANDROID_DOWNLOAD_URL` только после готовности подписанного APK или страницы релиза. Кнопка не открывает пустой адрес.

## Домен cortexapp.ru

Домен уже подключён к Vercel, а авторитетная DNS-зона `cortexapp.ru` активна в Cloudflare. Изменения записей делаются в Cloudflare; REG.RU остаётся регистратором.

**Не удалять и не перезаписывать MX, TXT, DKIM, SPF, DMARC записи VK Workspace.** Смена NS целиком не требуется. После распространения DNS проверьте HTTPS и страницу, затем нажмите «Проверить» в VK Workspace для метатега.

## Ограничения

Регистрация зависит от применённой SQL-миграции и настроенного Supabase Auth. Автовход в Android, рассылка о запуске и фактическое начисление бонусов требуют отдельного серверного этапа и интеграции в приложение. До коммерческого запуска необходимо заполнить реквизиты оператора, проверить размещение базы данных и согласия — см. `legal/LAUNCH-CHECKLIST.md`.
