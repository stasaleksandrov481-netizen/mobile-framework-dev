# CORTEX: обновления интерфейса без переустановки APK

## Граница возможностей

- HTML, CSS, JavaScript, иконки и другие ресурсы `app/src/main/assets/web/` можно обновлять без скачивания нового APK.
- Серверные функции/базу данных можно обновлять независимо от APK.
- Kotlin/Java, Android-компоненты, новые разрешения, нативные библиотеки и изменения manifest требуют нового **подписанного APK** или обновления через магазин. Android не разрешает безопасно заменить установленный нативный код обычным ZIP.

## Безопасность

Обновление подписано RSA-ключом (`SHA256withRSA`). В APK находится только публичный ключ. Закрытый ключ должен храниться вне GitHub и Vercel, в защищённом хранилище оператора. Если ключ или HTTPS-корень не настроен, автообновления полностью выключены.

Три файла релиза: `manifest.json`, `manifest.sig`, `web-v<version>.zip`. Телефон сначала проверяет подпись манифеста, затем SHA-256 и точный размер ZIP, ограничения на распаковку и наличие обязательных файлов. Пакет разворачивается во внутреннее хранилище приложения, становится активным атомарно и используется **со следующего запуска WebView**. При сбое WebView или отсутствующих основных JS-объектах CORTEX возвращает предыдущий пакет.

Обновления выполняются только из настроенного HTTPS-корня без перенаправлений. Веб-интерфейс по-прежнему доступен только через локальный `WebViewAssetLoader`, а JS-мост привязан к `appassets.androidplatform.net` и главному фрейму. Нельзя добавлять непроверенные сторонние скрипты: обновлённый JS обладает доступом к интерфейсу управления телефоном.

## Первичная настройка перед выпуском APK

1. Создать **отдельный** приватный ключ RSA 3072 вне репозитория (команда для OpenSSL):

   ```bash
   openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out /secure/path/cortex-web-update-private.pem
   ```

2. Экспортировать публичный ключ в Base64 одной строкой:

   ```bash
   openssl pkey -in /secure/path/cortex-web-update-private.pem -pubout -outform DER | openssl base64 -A
   ```

3. Настроить **GitHub Actions repository variables**:

   - `CORTEX_WEB_UPDATE_PUBLIC_KEY` — публичный Base64 из шага 2.
   - `CORTEX_WEB_UPDATE_ROOT` — точный HTTPS-корень статических файлов обновления, например `https://updates.example.org/cortex-web`.

4. Только после настройки переменных собрать APK с этим ключом и корнем. При смене корня или RSA-ключа потребуется новая нативная версия. Закрытый PEM **не добавлять** в CI и репозиторий без отдельного безопасного процесса управления секретами.

GitHub Actions запрещает публичную публикацию APK, если хотя бы один из параметров обновлений отсутствует. Это не позволяет случайно выпустить долгоживущую версию без механизма веб-обновлений. Сборки для локальной проверки по-прежнему возможны без обоих параметров; в них OTA выключен.

## Публикация новой версии веб-интерфейса

Из корня репозитория, с действующим закрытым ключом:

```bash
python3 tools/package_web_update.py --version 2026111601 --min-native 112 \
  --private-key /secure/path/cortex-web-update-private.pem \
  --output /tmp/cortex-web-update-2026111601
```

Загрузить содержимое выходного каталога в настроенный статический HTTPS-корень. Новая версия должна иметь **строго больший** номер. Не менять файлы ZIP или `manifest.json` после подписи. Клиент проверяет обновление не чаще одного раза в час, а после сетевой ошибки повторяет попытку не раньше чем через 10 минут. Активная задача ради обновления не прерывается.

Для проверки подписи на рабочем компьютере можно выполнить:

```bash
openssl pkey -in /secure/path/cortex-web-update-private.pem -pubout -out /tmp/cortex-web-update-public.pem
openssl base64 -d -in /tmp/cortex-web-update-2026111601/manifest.sig -out /tmp/cortex-manifest-signature.bin
openssl dgst -sha256 -verify /tmp/cortex-web-update-public.pem \
  -signature /tmp/cortex-manifest-signature.bin /tmp/cortex-web-update-2026111601/manifest.json
```

## Ограничения перед ЗБТ

- Проверить первую установку и обновление на физических Android 8–15+, а также без интернета, с повреждённым ZIP, неправильной подписью, нехваткой места и после убийства процесса.
- Проверить откат после ошибок JS/WebView и сохранение истории/настроек в `localStorage`.
- Настроить HTTPS-корень и RSA-ключ заранее. Пока этих двух значений нет, OTA намеренно не активен.
- Для новой версии AccessibilityService, нативных инструментов, разрешений или исправлений Android необходимо выпускать подписанный APK. Установка такого APK потребует системного подтверждения или механизма магазина приложений.
