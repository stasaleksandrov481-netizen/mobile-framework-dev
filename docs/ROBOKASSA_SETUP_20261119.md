## Серверный приём платежей

В `cortex-control/api/billing.js` вместо старого Platega API подготовлен переход на **Robokassa Merchant/Index.aspx**. Счёт формируется сервером, сумма берётся из защищённой RPC таблицы, email — из аутентифицированного запроса, подпись генерируется по Password #1. В подписанный Shp_order включается полный UUID заказа; InvId стабильно преобразуется из 60 бит UUID и проверяется на ResultURL. На ResultURL проверяются подпись Password #2, InvId, сумма, заказ и режим; только затем выполняется RPC подтверждения. При успехе — ответ `OK{InvId}`. Повторы подтверждения обрабатываются существующей идемпотентностью базы.

Ограничение: `provider_id` исторически UUID; до миграции схемы в качестве внутренней ссылки хранится UUID заказа (это **не** оригинальный OpKey транзакции Robokassa). **Refund API не активирован**: для него нужны Password #3 и OpKey, возврат делается через кабинет Robokassa. В панели кнопка автоматического возврата скрыта, чтобы не имитировать успех.

Параметры среды `cortex-control` (значения только в Vercel, не в GitHub):
- `ROBOKASSA_MERCHANT_LOGIN` — идентификатор магазина из кабинета.
- `ROBOKASSA_PASSWORD_1` — подпись счёта.
- `ROBOKASSA_PASSWORD_2` — проверка подписанного ResultURL.
- `ROBOKASSA_HASH_ALGORITHM` — `md5` по умолчанию, либо `sha256` в соответствии с настройками Робокассы.
- `ROBOKASSA_LIVE_APPROVED=true` — ставить только после проверки на подписанном стенде.
- `CORTEX_BILLING_MODE=live` — отдельное необходимое условие.
- `CORTEX_BILLING_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` — прежние серверные секреты (не выводить).
- БД `cortex_billing_config.checkout_enabled` должна разрешать оплату только после проверки бюджета и резервов.

**До наличия всех параметров, согласованной фискализации и тестового платежа реальные платежи не включать.** Даже при установке всех переменных ошибка подписи или недоступность callback приводит к невозможности подтвердить оплату. На сайте не включать «Оплатить», пока не доказано работоспособность всего цикла.

Технические адреса:
- Payment URL: `https://auth.robokassa.ru/Merchant/Index.aspx` (создаётся сервером).
- ResultURL: `https://<реальный-домен-cortex-control>/api/billing?webhook=1`, **POST** и публичный доступ без авторизации, подпись проверяет код.
- SuccessURL и FailURL: настроить на реально существующие страницы возврата, не использовать их для подтверждения платежа (только ResultURL).
- HTTPS, фискальные чеки для НПД и соответствие данных продавца проверить до включения.

## Отложенные вопросы

1. Проверить фактическую актуальность ФИО/ИНН и города в кабинете и опубликованном подвале.
2. Настроить Robochecks для самозанятого и электронные чеки.
3. Вернуть автоматические refunds только после безопасной интеграции Password #3/OpKey; до этого вручную через кабинет.
4. Провести полноценную тестовую оплату и один небольшой реальный платёж только после одобрения магазина; сверить выдачу тарифа, идемпотентность, возврат, баланс.
5. Проверить, что бекенд Vercel `cortex-control` действительно выкатывается отдельно от веб-сайта.
